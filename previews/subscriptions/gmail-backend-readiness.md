## Isolated implementation
- Server handler accepts POST start/status/disable/disconnect from exact fixture origin, and a GET callback with one state/code. Every request requires independently verified current admin/session and recent step-up (five minutes). The OAuth state hash, encrypted PKCE verifier and actor/session binding are consumed atomically; expire in five minutes. Generation fencing prevents a callback from restoring a disabled/disconnected connection. No automatic enable after exchange.
- New private read-only admin proof invokes the existing admin_session_state gate; uses current session AMR and approved, unrevoked passkey proof, not client role fields. Public wrapper SECURITY INVOKER, authenticated execute only. Existing authentication files remain unchanged. CI uses metadata-only auth fixture, not live auth.
- AES-256-GCM external key, unique random IV, version-bound AAD, authenticated ciphertext. Access tokens are memory-only; refresh token stored as ciphertext. Distinct control/dispatch roles, forced RLS, no client table grants, fixed query adapters and bounded transactions. Key version mismatch fails closed. Reconnect/rotation requires controlled procedure; no automatic credential rotation. Disconnect clears local encrypted credential before mock provider revocation; if revocation fails, manually remove app access at Google.
- Send-only transport uses fixed token, revoke and Gmail messages.send endpoints through a mandatory injected fixture transport. No default network client. Fixture-only client ID/secret/token/recipient and callback URL. The real Gmail API is not authorized and no real mail can be constructed by the synthetic renderer.
- Existing outbox admission remains access-only; reserve under destination, connection and quota locks before dispatch. Charge one allowance per reserved attempt (80/day, 2400/month UTC synthetic caps), wipe queued payload, persist ambiguous hold before network boundary. Separate one-use dispatch ticket checks generation, connection and exact message/token eligibility again immediately before mock send. No blind resends after timeout, crash or unknown result. Acceptance is not delivery proof. 401/403/429 pause dispatch; actual provider quota/account limits need review.
- Status response exposes connected/enabled only. Emergency disable/disconnect invalidate outstanding OAuth state and future dispatch tickets. A send already in flight cannot be recalled. No live dashboard controls, real activation route or provider event ingestor deployed. Final role revokes historical simulation worker entrypoints; historical tests still run before final schema stage.
- No signup confirmation/welcome email. SMS remains confirmed opt-in. info@ reply-to and existing inquiry routing unchanged.
