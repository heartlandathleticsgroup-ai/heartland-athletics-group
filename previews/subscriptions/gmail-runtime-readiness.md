## Session handoff and callback
Static GitHub Pages cannot hold server secrets or a callback cookie on a server runtime origin. The staged design uses an exact allowlisted HAG admin origin: POST prepare with current user bearer; validate the existing user-context admin proof; return a 60-second opaque launch grant, never the bearer. Top-level form POST grant to the future runtime origin, not a query parameter or cross-site cookie request. Grant digest and encrypted bearer/actor/session stored server-side, consumed once, with connection generation fencing. A five-minute HttpOnly Secure SameSite=Lax __Host- cookie is set on the runtime's own origin. Callback GET consumes cookie/state pair once and revalidates current admin proof; existing OAuth state is independently consumed. Clear cookie and redirect to fixed no-secret completion page. Disable invalidates both grants and callback states. No actual Google redirect is executed in isolated mode.
Do not use real URLs until a concrete hosted runtime and exact authorized callback domain/path are verified. Current runtime URL https://preview.invalid is a reserved fixture, not a registerable production redirect. Future deployment must test top-level form navigation on Safari and actual Supabase JWT/session proof, enforce fresh TOTP/approved passkey, verify origin, redact callback queries at every log/proxy layer, and implement same-origin result/control surface or approved cross-origin bearer control API. Current UI preview is an offline fictional state simulator, not attached to the live admin dashboard.

## Google HTTP and delivery
Transport boundary uses fixed token, revoke and messages.send URLs, POST only, no redirects, cookies, caching, referrer or automatic retries. Bounded request/response (64 KiB), 5-second deadline, JSON response validation, fixed one-recipient synthetic MIME. It requires injected mock fetch and refuses global fetch or production mode. Production-shaped transport is prepared, not operational; actual runtime adapter, live credential parsing and recipient/alias acceptance test remain release gates. Only request gmail.send; do not broaden access to inspect inbox or sent mail. Google API send acceptance is not delivery. Ambiguous reservation remains non-retryable even after crash. Cap unresolved holds at 500, list at most 50 oldest after one minute, operator can close as unverified or manually observed acceptance, with actor/time/disposition recorded; factual outcome stays unchanged. No resend control. Cleanup expired state and closed metadata older than 90 days, never unresolved holds. Emergency disable stops new dispatch tickets; in-flight messages cannot be recalled.
