# H.A.G. CMS — independent release

Draft/save/publish/unpublish for news, events, sponsors. Existing static site content stays intact; approved CMS records appear in an additive homepage section. No sponsor records imported or published automatically. Sponsor permission is required before publication; amounts and contact information are not stored. Use existing local raster image paths; upload/storage tooling is deferred. No Gmail, subscription, SMS, workers, app or DNS changes. Auth gate reused without alteration. Private draft and audit tables have RLS and no client table grants; public snapshot has read-only RLS and no private fields. Private definer functions guard every admin call; public wrappers are invoker functions. Limit 200 saved entries per kind, no permanent deletion in this initial release. Existing published snapshot remains visible until explicit publish/unpublish. CI uses a fixture access gate and disposable PostgreSQL; actual hosted gate and device regression require release acceptance.

Deployment order (separate from PR #28): review CI and production compatibility, apply schema, verify privileges and zero publications, then publish web assets, verify password/MFA/passkey and Formspree. Public feed must remain empty until owner publishes a record. Rollback: revert website assets and revoke CMS public read and authenticated RPC permissions; retain draft/audit data. Never alter the existing auth gate. No additional services or credentials.
