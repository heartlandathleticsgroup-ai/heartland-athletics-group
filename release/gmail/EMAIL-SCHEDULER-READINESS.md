# Secure email processing — staged
Existing outbox atomically queues at most one welcome for eligible email consent; dispatch reservation and suppression checks run before Gmail call, ambiguous outcomes never resend. Keep current production Gmail control and its secret configuration. Never deploy aggregate runtime over control. Candidate signed scheduler contract adds exact endpoint/method, HMAC-SHA256 with independent private key, 60-second window, UUID nonce, fixed empty JSON, durable nonce consumed once before pump. No reusable bearer secret in queued pg_net headers. No scheduler is installed. Hosted database currently has pg_cron and pg_net available but not installed; Supabase Vault and pgcrypto installed. For eventual approved activation use a narrow SQL signer reading the dedicated key from Vault and enqueue only ephemeral timestamp/nonce/signature. Provision shared key privately, no SQL result or GitHub exposure; validate cross-language HMAC with actual hosted fixture, deny replay globally, bound nonce cleanup, monitor costs and rate limits, and do not schedule until normal email sending is authorized. Current candidate intentionally has no grant or live transport. One-click RFC 8058 unsubscribe, external sender authentication review, hosted worker/gateway acceptance, operational retention and consent cutover remain release gates.
