# Administrative OAuth handoff — unpublished release preparation
The production administrator page remains unchanged with form-action 'none'. The draft page permits exactly the Supabase launch endpoint and Google OAuth authorization endpoint for the later connection-only flow; scripts, connect-src, base-uri and object-src restrictions are unchanged. Gmail UI release flag and hosted source lock remain false. The route validates the complete exact Google parameter set, including fixed scope, callback, prompt, login hint and PKCE fields. The isolated runtime test verifies the redirect origin/path, no-store, no-referrer and no grant in the URL. No real browser navigates to Google in CI.
Supabase shared-domain functions do not support serving normal HTML pages; do not buy a custom domain for this flow. The top-level form POST + 303 uses the existing callback bridge and avoids reliance on HTML response rendering. Browser handling of form-action redirects differs, and source path restrictions may not be enforced after redirects. Actual Safari/Chrome redirect and first-party cookie acceptance remain mandatory before publishing or initiating OAuth. If blocked, stop and redesign rather than add wildcards, disable CSP or broaden scopes. No OAuth authorization or hosted changes in this batch.
