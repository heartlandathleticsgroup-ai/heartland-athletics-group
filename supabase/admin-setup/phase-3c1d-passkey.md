# Phase 3C.1D — approved passkey sign-in (draft, not deployed)
Native Supabase passkey login supplies AAL1 and its hosted WebAuthn flow may not require local user verification. Do not treat AAL1, a client flag, or a passkey method alone as MFA. The gateway requires UP+UV in the exact signed bytes and forwards the assertion to the fixed Supabase Auth endpoint, whose verifier checks signature/challenge/RP/origin and consumes the challenge. Only tokens returned by that endpoint are inspected, then validated with Auth. A service-only SQL RPC checks active staff, existing verified TOTP, matching native session/AMR, and a specific manually approved credential. Ordinary password logins still require AAL2. The passkey alternative does not change the provider's AAL claim. Native registration requires AAL2 when TOTP is enabled; newly registered credentials are not automatically approved.
